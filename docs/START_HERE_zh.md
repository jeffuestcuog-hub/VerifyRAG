打开 `VerifyRAG_Colab.ipynb`。推荐在 Google Colab 中打开，并上传本项目压缩包，按顺序运行。

先看三个例子：

1. 正常问题：`How do I use uvm_config_db get and set?`
2. 不存在的 API：`How do I use uvm_magic_auto_debug to fix my testbench?`
3. 版本不匹配：选择 `1.2`，询问 `uvm_config_db`。

第一种输出原文证据；第二种应因缺少对应 API 证据拒答；第三种应提示版本不支持。

## 第三步：完成你自己的专业判断

每次评测会生成 `results/.../human_review.csv`：

- `correct_0_1`：技术内容是否正确；
- `usable_0_1`：能否帮助真实工程任务；
- `evidence_entails_claim_0_1`：所引原文是否真的支持该结论；
- `counterfactual_wrong_if_answered_0_1`：对拒答案例，强行回答是否会错；无法判断留空并解释。

请你和至少一位了解 UVM 的同学分别核验。不要把“引用格式正确”填成“答案正确”。
不得预填签名、同学意见、个人体验或不存在的实验。

## 最容易误读的几个数字

- **44%** 是这个项目占整门课的权重。
- 项目内部评分：问题价值 15%、取舍分析 25%、实现 35%、演示表达 25%。
- **Hit@5**：前五条检索结果中有正确证据的题目占比，不是答案准确率。
- **引用校验通过**：引用存在、文字确实出自原文、UVM 标识符有出处，不证明结论正确。
- **实测 API 成本**：本次批次为 USD 0.00915030；它不是工程效率或商业收益。

## 与原提案的差异

第一版用官方开源实现中的 24 个文件，未收录完整 Cookbook 或公司内部资料。
检索使用本地 BM25 / TF-IDF 与融合，未调用付费嵌入模型。这个范围调整降低依赖和复现成本，
但语义改写问题可能查不到；报告必须如实说明，不能把本地词频向量称为神经语义嵌入。

后续若增加 MiniLM 等语义检索，应在开发集上比较，重新冻结设计，再使用新的保留集验证。
